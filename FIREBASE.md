# Firebase: включение аккаунтов DEADAIM 3.0

Твой проект **deadaim** уже указан в `firebase-config.js`. Создавать второй проект и менять ключи не нужно. Настройка состоит из двух обязательных действий.

## 1. Включить вход по почте и паролю

1. Открой [Firebase Console](https://console.firebase.google.com/) → проект **deadaim**.
2. Найди **Authentication** через меню или поиск продуктов.
3. Открой **Sign-in method** (способы входа).
4. Нажми **Add new provider** → **Email/Password**. Если этот провайдер уже есть, открой его.
5. Включи первый переключатель **Email/Password** и нажми **Save**.

Email link / passwordless для этого сайта не нужен. Старый Anonymous можно оставить включённым: регистрация привяжет существующего анонимного пользователя к email в том же браузере.

Официальная инструкция: [Password Authentication](https://firebase.google.com/docs/auth/web/password-auth).

## 2. Опубликовать новые правила Firestore

1. В этом архиве открой файл **firestore.rules** обычным текстовым редактором.
2. Скопируй **всё** содержимое.
3. В Firebase открой **Firestore Database** → существующую базу **(default)** → вкладку **Rules**.
4. Выдели весь текст старых правил и замени скопированным текстом.
5. Нажми **Publish**. Если редактор показывает ошибку, не заменяй правила на `allow read, write: if true`: передай текст ошибки для исправления.

Правила нужно заменить целиком. Новые правила включают поддержку старых комнат v2, поэтому существующие документы не удаляются. Коллекции вручную создавать не нужно: приложение создаёт их при регистрации, заявке и сохранении серии.

Одного обновления `firestore.rules` на GitHub недостаточно: Firebase начинает применять правила после **Publish** в консоли.

Официальное описание: [Security Rules](https://firebase.google.com/docs/firestore/security/get-started).

## 3. Обновить сайт и проверить

Обнови файлы по [GITHUB-UPDATE.md](GITHUB-UPDATE.md), дождись публикации GitHub Pages и открой сайт. Обнови страницу через Ctrl+F5.

1. Нажми **Создать аккаунт**.
2. Придумай ник: например `alisher_7`. Допустимы латинские буквы, цифры и `_`, 3–20 символов. Регистр не важен.
3. Введи email и пароль от 8 символов, повтори пароль. Подтверждать email не нужно, но доступная тебе почта нужна для восстановления пароля. Не используй чужой адрес.
4. После входа в шапке появится твой ник.
5. Заверши короткую тренировку на 30 секунд. Под профилем должно появиться сообщение о сохранении серии.
6. Нажми **Синхронизировать статистику** и убедись, что серия остаётся в истории после перезагрузки.
7. Друг регистрируется отдельно. Введи его точный ник в профиле → **Найти** → **Добавить в друзья**.
8. Друг нажимает **Обновить ↻** в списке заявок и **Принять**.
9. Обнови список у себя → **Статистика**. Сравниваются серии с текущими настройками режима, сложности, времени, формата и кода челленджа.

Для проверки двух аккаунтов на одном компьютере используй отдельный профиль браузера или окно инкогнито. На общем компьютере выходи из аккаунта после тренировки.

## Перенос старой истории

- На том же устройстве и том же адресе GitHub Pages локальная история остаётся на месте.
- После регистрации нажми **Перенести гостевую историю**. Она копируется в текущий аккаунт; исходная история не удаляется.
- Если регистрация выполняется поверх сохранившегося Anonymous-входа, UID останется прежним.
- При входе в уже существующий email откроется его аккаунт. Перенос гостевых результатов делается отдельной кнопкой.
- Старые комнаты v2 не удаляются из Firebase. Их интерфейс заменён друзьями; удалённая история комнат автоматически не импортируется. Перенос доступен для истории, сохранившейся на устройстве.
- Если ник занят после создания Auth-аккаунта, форма предложит выбрать другой. Повторять регистрацию и пароль не нужно.

## Что хранится

| Где | Данные и доступ |
| --- | --- |
| Authentication | Email и пароль обрабатывает Firebase; сайт не сохраняет пароль в Firestore |
| deadaimNames | Уникальный ник → UID; поиск точного ника для вошедших пользователей |
| deadaimProfiles / UID | Ник и дата создания; профиль доступен вошедшим пользователям |
| … / sessions | Результаты; пишет владелец, читают владелец и принятые друзья |
| … / private / settings | Только владелец: сенса, DPI, калибровка, цвет, формат и звук |
| deadaimLinks | Заявки и дружба; подтверждает только получатель |
| deadaimRooms | Сохранённые групповые данные старой версии |

Экран читает последние 500 серий; друзья и заявки обновляются кнопкой, без постоянной подписки. Карта промахов показывается для последней сыгранной в этой вкладке серии, её точки не отправляются в облако.

Результаты рассчитывает браузер, серверного античита нет. Это прототип для дружеских тренировок. Правила прошли 7 локальных сценариев доступа; перед широким публичным запуском стоит отдельно проверить правила и ограничения на спам/расходы.

## Если что-то не работает

| Сообщение | Действие |
| --- | --- |
| Включи Email/Password | Выполни шаг 1 и нажми Save |
| Нет доступа / permission-denied | Проверь, что опубликован полный файл правил v3 в проекте deadaim, базе (default) |
| Ник занят | Укажи другой ник в той же форме |
| Email уже зарегистрирован | Переключись на вход или восстанови пароль |
| Не удалось войти | Проверь email и пароль; регистр пароля имеет значение |
| Серия сохранена локально | Восстанови интернет и нажми «Синхронизировать статистику» |
| Друг не найден | Нужен точный ник, друг должен закончить регистрацию |
| unauthorized-domain | Authentication → Settings → Authorized domains: добавь домен сайта, например `username.github.io`, без `https://` и пути репозитория |

В архиве уже находится публичная web-конфигурация твоего проекта. Service-account JSON, приватные ключи и пароли на GitHub не загружай. Google Analytics в приложение не подключён.

Рабочий проект Firebase и GitHub из этой версии автоматически не обновлялись. После двух настроек выше нужно пройти проверку с реальными аккаунтами.
